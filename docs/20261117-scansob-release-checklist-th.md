# ส่งทีม ScanSob: ชื่อระบบเช็คชื่อและรายการตรวจรับ

จากนี้ใช้ชื่อ **ระบบเช็คชื่อ** สำหรับผู้ใช้ แทนชื่อ MathQuest (ชื่อเดิมใน repo และ API) งานนี้ไม่เปลี่ยน endpoint, สัญญาคะแนน 1.0 หรือข้อมูลการเชื่อมต่อเดิม

## งานแก้ก่อนปล่อย

1. **เปลี่ยนข้อความที่ครูเห็น** ใช้ **เชื่อมต่อระบบเช็คชื่อ**, **ขออนุมัติส่งคะแนน**, **ส่งคะแนนไประบบเช็คชื่อ** ในตั้งค่า พรีวิวส่งคะแนน สถานะ ข้อผิดพลาด และหน้าประวัติ เก็บชื่อโรงเรียนปลายทางจริงไว้ แสดงคนละส่วนกับชื่อระบบ ถ้าข้อมูลเก่าให้ค่า fallback เป็น `MathQuest` ให้แปลตอนแสดงผล ไม่เขียนทับ connection เก่า
2. **คงค่าทางเทคนิค** ไม่เปลี่ยน API path, action, schema version, UUID โรงเรียน, idempotency key, ชื่อ environment variables `MATHQUEST_*` หรือคีย์/ข้อมูลที่บันทึกไว้ ค่า `MATHQUEST_DESTINATION_LABEL` ใช้แสดงชื่อปลายทาง ไม่ใช่ข้อมูลพิสูจน์สิทธิ์ ปรับเฉพาะค่าที่ตั้งไว้เป็นชื่อเดิม ไม่แทนชื่อโรงเรียนทุกแห่งด้วยชื่อระบบ
3. **แยกการหยุดคำขอใหม่จากการกู้คำขอเดิม** เมื่อผลส่ง `request_signed` ยังไม่แน่ชัด ให้กู้รายการเดิมด้วย Request ID, JSON และรอบเปิดรับเดิม ไม่เรียก `status` ก่อนการส่งซ้ำครั้งที่จำเป็น และไม่สร้าง attempt ใหม่โดยอัตโนมัติ อย่าให้ flag เริ่มคำขอใหม่ตัดการตรวจสถานะหรือยกเลิกรายการที่บันทึกแล้ว ถ้ายังแยกกู้จาก flag ไม่ได้ ให้พักรับที่ระบบเช็คชื่อก่อนและจัดการรายการค้างก่อนปิด flag ฝั่ง ScanSob
4. **ไม่ fallback ไปกรอกรหัส** ตรวจ release ที่จะ Deploy ว่าเอาช่องรหัสและการเปิดคำขอใหม่ด้วยรหัสออกจากทั้งหน้าเว็บและ API แล้ว แยกข้อความ **ระบบเช็คชื่อยังไม่เปิดรับคำขอ** จาก **ตรวจความพร้อมของระบบเช็คชื่อไม่ได้** โดยไม่เปิดทางรหัสกลับมาในทั้งสองกรณี

## ตรวจรับบน staging ก่อนเปิดจริง

| ตรวจอะไร | ผลที่ต้องได้ |
| --- | --- |
| การตั้งค่าและเวอร์ชัน | ScanSob ใช้รุ่นที่จะ Deploy และตรวจพบ SQL 024; ใช้ HTTPS origin, UUID โรงเรียน และคีย์ของ staging ให้ตรงกับระบบเช็คชื่อ ห้ามเปิด flag ใน Production เพื่อทดสอบ |
| ชื่อบนหน้าจอ | ชื่อ **ระบบเช็คชื่อ** แสดงในข้อความถึงครู ไม่มีชื่อเก่าโผล่เป็นชื่อระบบในสถานะปกติ ข้อผิดพลาด และ connection เดิมที่เดิมใช้ชื่อ fallback ส่วนชื่อโรงเรียนจริงยังถูกต้อง |
| ขออนุมัติโดยไม่ลงอีเมลล่วงหน้า | ครู Google จำลอง A และ B ที่ได้รับสิทธิ์ใน ScanSob และเป็นเจ้าของคนละ Workspace ขอได้โดยไม่กรอกรหัสหรืออยู่ในรายชื่อเก่า แอดมินอนุมัติ A และปฏิเสธ B; B ส่งคะแนนไม่ได้ และทั้งคู่เห็น/จัดการเฉพาะรายการของตน |
| คำขอซ้ำและคำตอบหาย | กดซ้ำหรือเปิดสองแท็บไม่สร้างคำขอซ้ำ ลองทำคำตอบหายหลังปลายทางรับแล้ว ให้กู้คำขอเดิมได้ ทดสอบพักรับขณะมีคำขอรอหรือผลส่งยังไม่ชัดเจน |
| อนุมัติไม่เท่ากับส่งคะแนน | A ขึ้นเชื่อมต่อเมื่อเก็บสิทธิ์แล้ว โหมดเริ่มต้นเป็น `manual` และ **คิวส่งของ Workspace ทดสอบเป็น 0** ก่อนครูกดส่ง |
| ส่งและถอนคะแนน | กดส่งชุดสอบยืนยันแล้วด้วยข้อมูลจำลอง เช่น รับสำเร็จ 1 และจับคู่ไม่ได้ 1 ตรวจใบตอบรับรอบเดียวกันทั้งสองฝั่ง ส่งข้อมูลเดิมซ้ำไม่เพิ่มยอดและถอนคะแนนได้ |
| การเชื่อมต่อเดิม | Workspace ที่เชื่อมอยู่แล้วใช้ token เดิมต่อได้ ไม่ต้องจับคู่ใหม่ การพักรับคำขอไม่ระงับคะแนนที่เคยส่งหรือการเพิกถอน |

**สิ่งที่ให้ทีมส่งกลับ:** commit ที่ใช้จริงของ ScanSob, ระบุว่า staging ลง SQL 024 แล้วหรือยัง, ชื่อการ Deploy ของทั้งสองฝั่ง และผลผ่าน/ไม่ผ่านของแต่ละกรณีพร้อมขั้นตอนแก้ที่เหลือ แนบเฉพาะผลจากข้อมูลจำลอง ไม่แนบ token, signing key, session หรือข้อมูลนักเรียนจริง
