# แก้การล้างข้อมูลนักเรียนโดยไม่บังคับวันที่

## สาเหตุของข้อผิดพลาดเดิม

`reset_school_for_new_semester` รุ่นก่อนมีคำสั่งล้างเซสชันครูที่ไม่มี `WHERE` จึงถูก `safeupdate` บล็อก ข้อผิดพลาดที่ท้ายฟังก์ชันทำให้ transaction ย้อนกลับทั้งชุด ไม่ได้ลบความคืบหน้าสำเร็จไปบางส่วน

รุ่นนี้ล้างเซสชันโดยระบุเงื่อนไขจับคู่บัญชีอย่างชัดเจน ไม่ปิด `safeupdate` และไม่ใช้ `TRUNCATE`

## สิ่งที่เปลี่ยน

- ปุ่มล้างข้อมูลเรียก RPC `reset_school_progress` โดยส่งเฉพาะ token ครู รหัสผ่านครู และเวอร์ชันข้อมูล
- ไม่ถามภาคเรียน ปี วันเปิด หรือวันสิ้นสุดก่อนล้างข้อมูล และไม่ใช้วันใดเป็นเงื่อนไขลบ
- ลบความคืบหน้าของ role `STUDENT` ทุกห้องทุกวันที่: การเข้าเรียน คะแนน/XP/Level/เหรียญ/แต้มพิเศษที่คำนวณจากประวัติ รายการแลก/รับของฟรี สัตว์เลี้ยงและประวัติสัตว์เลี้ยง คำขอ OTP และสถานะอ่านแจ้งเตือนของฟรี ไม่มี archive
- คงบัญชี รหัสประจำตัว ชื่อ ห้อง รหัสผ่าน รูปโปรไฟล์ สินค้า ข้อมูลครู และการตั้งค่าโรงเรียน/ภาคเรียนไว้
- ชื่อภาคเรียนเปลี่ยนแยกในตั้งค่าได้ วันเริ่ม–สิ้นสุดยังเป็นตัวเลือกสำหรับรายงาน ไม่ใช่เงื่อนไขรีเซ็ต
- ยังแสดงจำนวนข้อมูลจริง และต้องติ๊กยืนยัน พิมพ์ข้อความยืนยัน และกรอกรหัสผ่านครูก่อนลบ
- ยังป้องกันการล้างระหว่างเปิดคาบหรือมีออเดอร์ pending และปฏิเสธคำขอจากเว็บรุ่นข้อมูลเก่าหลังล้างสำเร็จ
- RPC 7 พารามิเตอร์เดิมยังอยู่เพื่อรองรับเว็บเก่า และไม่บังคับวันที่ในฐานข้อมูล แต่เว็บเก่าจะยังมีช่องวันที่จนกว่า Deploy โค้ดใหม่

## ขั้นตอนติดตั้ง

1. สำหรับเครื่องที่รัน `20261010_01_school_term_reset_otp.sql` แล้ว ให้รันเฉพาะไฟล์ใหม่ `20261010_02_reset_progress_without_dates.sql` ใน Supabase SQL Editor
2. ตรวจว่ารันสำเร็จ ไม่มี error การรันไฟล์นี้แค่เปลี่ยนฟังก์ชัน ไม่เรียกรีเซ็ตและไม่ลบข้อมูลทันที
3. Deploy โค้ดหน้าเว็บใหม่ แล้วกด Ctrl+F5 ออกจากระบบและเข้าสู่ระบบครูใหม่
4. ตรวจในตั้งค่าว่าปุ่มเป็น “ตรวจสอบและล้างข้อมูลนักเรียน” และหน้าต่างยืนยันไม่มีช่องภาคเรียน/วันที่

ไม่ต้องรัน `supabase_complete.sql` หรือ SQL ติดตั้งเดิมซ้ำ ไม่ต้องเพิ่มคอลัมน์หรือปิด `safeupdate`

## เมื่อต้องการล้างข้อมูลจริง

1. ส่งออกรายงานที่ต้องการเก็บก่อน เพราะหลังล้างจะพิมพ์ประวัติเดิมไม่ได้
2. ปิด/ยกเลิกคาบที่ค้าง และจัดการรายการแลกของที่ยัง pending
3. เข้า ตั้งค่า → ตรวจสอบและล้างข้อมูลนักเรียน ตรวจจำนวนข้อมูลและบัญชีที่จะคงไว้
4. ติ๊กยืนยัน พิมพ์ “ลบทั้งหมด” กรอกรหัสผ่านครู แล้วกดลบข้อมูลนักเรียนถาวร
5. เมื่อล้างสำเร็จ เข้าสู่ระบบใหม่ แล้วตั้งภาคเรียนเป็น 2/2569 หรือค่าที่ต้องการในส่วนภาคเรียน ไม่ต้องระบุวันที่หากไม่ใช้ช่วงวันในรายงาน

## การทดสอบ

PGlite ตรวจการรัน migration/patch ซ้ำ ล้างได้เมื่อวันภาคเรียนว่าง ลบข้อมูลข้ามปี/ทุกห้อง คงบัญชีและค่าเทอม ย้อนกลับครบเมื่อจำลองความผิดพลาดตอนล้างเซสชัน รวมถึงสิทธิ์และ RPC เก่า Tests ตรวจทุก DELETE ว่ามี WHERE เพิ่มเติม เพราะ PGlite ไม่มี extension `pg-safeupdate` ของ production

Playwright ใช้ fixture และบล็อก Supabase จริง ตรวจว่าหน้าล้างไม่มีช่องวันที่/เทอม มีการยืนยันก่อนเรียก RPC แจ้งชื่อ SQL ใหม่เมื่อยังไม่ติดตั้งและกดลองใหม่ได้ ล้างสำเร็จให้ login ใหม่ ตรวจ modal ที่ 320/390/768/1280px

ยังไม่ได้รัน patch หรือล้างข้อมูลบน Supabase จริง การทดสอบไม่มีข้อมูล production
