## ตรวจหน้าหลักและ PIN

- ตรวจขนาด 320x568, 360x740, 390x844, 430x932, 768x1024 และ 1280x900 โดยรอขนาด viewport และเฟรม layout ให้เสถียรก่อนวัด
- ปุ่มเช็คชื่ออยู่เหนือเมนู fixed ที่ 360px ขึ้นไปในข้อมูลตัวอย่าง จอ 320px/จอเตี้ย/ข้อความยาวยอมให้เลื่อน
- รองรับวาง PIN เลขศูนย์นำหน้า เลขไทย และแตะเปลี่ยนเลขตรงกล่องที่เลือก
- กรอกไม่ครบไม่บันทึก รหัสผิด/ไม่มีคาบ/หมดอายุ/ผิดห้องแสดง error ตามจริง
- ปัญหา GPS ไม่ทำให้ PIN ถูกระบุว่าผิด ไม่มีการขอตำแหน่งตอนเปิดหน้าจอ
- สำเร็จหลังผลเซิร์ฟเวอร์เท่านั้น ป้องกันส่งซ้ำระหว่างรอผล และ duplicate ไม่จำลองคะแนนเพิ่ม
- ตรวจชื่อ keyframes ของ wave และการคืน state/ล้าง PIN หลัง 3 วินาที ไม่อ้างว่าสกรีนช็อตนิ่งพิสูจน์ความลื่นของการเคลื่อนไหวได้
- โหมด reduced motion ไม่มีการสั่นหรือ wave แต่ยังมีสีและข้อความ
- ขยายข้อความ 200% ช่องสูงอย่างน้อย 100px ข้อความเว้นจากช่องอย่างน้อย 12px และเลื่อนขึ้นเหนือเมนูล่างได้

## ตรวจการติดตั้งและการปิดหน้าต่าง

- จำลอง `beforeinstallprompt` เพื่อทดสอบการใช้ครั้งเดียว ปฏิเสธคำขอ และวิธีผ่านเมนูสำรอง ไม่ใช่การติดตั้ง Android จริง
- iOS ไม่มีปุ่มติดตั้งอัตโนมัติ มีคำแนะนำ Safari และภาพไอคอนเป็นขั้นตอน
- ตรวจตำแหน่งปุ่มลอยไม่ชนปุ่มเช็คชื่อหรือเมนู หากพื้นที่ไม่พอปุ่มลอยซ่อน แต่เข้าผ่านเมนูได้
- `appinstalled` ที่จำลองทำให้ปุ่มลอยซ่อน ไม่ใช้การกดยอมรับ prompt แทนหลักฐานติดตั้งเสร็จ
- พื้นที่ว่างภายในไม่ปิด แตะ backdrop ปิดและคง PIN เดิม
- draft กรอบที่ยังไม่บันทึกถามก่อนออก ยกเลิกคำถามแล้ว draft ยังอยู่
- กด Tab หกครั้งในคำถามทิ้งข้อมูล โฟกัสยังอยู่หน้าต่างบนสุด Escape กลับฟอร์มแม่และคืนโฟกัส
- หน้าครอปรูปไม่ปิดเมื่อเริ่มลากจากข้างในไปปล่อยข้างนอก หรือขณะกำลังประมวลผล
- แตะพื้นหลังนอกครอปจริงเปิดคำถามทิ้งรูป ยกเลิกแล้วแก้ต่อได้ ยืนยันทิ้งไม่อัปโหลดหรือเปลี่ยนรูปจริง
- ยืนยันว่า fixture ไม่ส่งคำขอไป Supabase production

## ผลตรวจ Impeccable

ตรวจ static ด้วย `detect` หนึ่งครั้งกับ CSS/JS ใหม่ ได้ `[]` ไม่ใช่ผลรับรอง accessibility ของทั้งแอป

ผู้ตรวจแยกพบปัญหา 4 จุด: โฟกัสหน้าต่างซ้อน, backdrop ครอป, ปุ่มลอยชนปุ่มหลัก และข้อความ PIN ขยายใหญ่ หลังแก้และส่งหลักฐานใหม่ ผู้ตรวจให้ผล:

| จุดที่ตรวจซ้ำ | ผล |
| --- | --- |
| โฟกัสคำถามทิ้งข้อมูลและคืนโฟกัส | resolved |
| ครอป: แตะนอก/ระหว่างบันทึก/ลาก | resolved |
| ปุ่มติดตั้งเว้นระยะจากส่วนสำคัญ | resolved |
| PIN และข้อความเมื่อขยาย 200% | resolved |

**disposition: ship** ครอบคลุมเฉพาะ 4 จุดที่ตรวจแก้ ไม่ใช่การรับรองว่าทั้งโปรเจกต์ไม่มีข้อผิดพลาด ผู้ตรวจไม่ได้รันชุดทดสอบเอง

การจัดทำเอกสารทำต่อในงานหลักแทนตัวช่วยที่หยุดทำงาน ไม่เขียนทับ `PRODUCT.md`, `DESIGN.md` หรือ sidecar เดิม และไม่แก้ schema/context drift ของเอกสารสกิลเป็นผลข้างเคียง

## ภาพหลักฐานและไอคอน

ภาพอยู่ใน `tmp/student-home/` ซึ่งถูก ignore มีข้อมูลนักเรียนจำลองเท่านั้น ภาพ `home-*` เป็น viewport ของแต่ละขนาด ส่วน `text-zoom.png` เป็น viewport ที่เลื่อนให้เห็นผลตรวจ ไม่ใช่ภาพทั้งเอกสาร

ไอคอนแอป 4 ไฟล์ย่อจากโลโก้เดิม ต้นฉบับไม่เปลี่ยน ขนาดไฟล์หลังบีบอัดและฝังที่มาคือ 15,250 / 17,312 / 118,900 / 61,037 bytes การสแกนข้อมูลที่มาได้ 4 rasters, 0 missing ไม่มีภาพที่สร้างด้วย AI ใหม่ในงานนี้ ภาพวิธีติดตั้งใช้ Font Awesome ตามชุดเดิม

## สิ่งที่ยังไม่ได้รับรอง

- การติดตั้งจริงและการกลับจาก Google OAuth ใน standalone บน Android/iPhone/iPad ต้องตรวจหลังเผยแพร่ HTTPS
- ไม่ได้ใช้บัญชี production หรือทดลอง GPS บนอุปกรณ์จริง
- การจำลอง viewport สั้นไม่ได้แทนคีย์บอร์ดและ permission sheet ของ Safari จริงทั้งหมด
- ไม่ได้ทดสอบครบทุก screen reader หรือรับรองมาตรฐาน WCAG
- ไม่ได้ Deploy หรือยืนยันสถานะ Vercel และไม่มีการรัน SQL ใหม่

## รันทดสอบซ้ำ

ต้องมี Playwright, Edge/Chromium และ Sharp ในสภาพแวดล้อมทดสอบ เช่นเดียวกับชุดทดสอบเดิม ฐานทดสอบ SQL ใช้ PGlite/PostGIS แยกจาก production

```powershell
node scripts/test-student-home-ui.cjs
node scripts/test-student-install-assets.cjs
node scripts/test-profile-frames-ui.cjs --no-capture
node scripts/test-attendance-location-ui.cjs --no-capture
```

หากสร้างไอคอนใหม่ด้วย `scripts/prepare-app-icons.cjs` ต้องฝังที่มาด้วย `impeccable embed-prompt` อีกครั้งก่อนทดสอบ asset ไฟล์ PNG ปัจจุบันมีข้อมูลที่มาครบแล้ว
