# อัปเดตภาคเรียน หน้าใช้งานครู และ OTP

## ไฟล์ SQL ที่ต้องรัน

ใช้เฉพาะ `20261010_01_school_term_reset_otp.sql` ใน Supabase SQL Editor สำหรับอัปเดตรอบนี้ ไม่ต้องรัน `supabase_complete.sql` ซ้ำ

Migration เพิ่ม metadata ภาคเรียน, สิทธิ์ครูแบบ token สำหรับคำสั่งใหม่, RPC เปิดคาบ/รีเซ็ต และ OTP แบบแยกขั้นตอน การรัน migration **ไม่ลบคะแนนหรือประวัตินักเรียน** และรันซ้ำได้

ค่าเริ่มต้นภาคเรียนคือ 1/2569 โดยไม่กำหนดวันเริ่ม–สิ้นสุดแทนโรงเรียน ข้อมูลนักเรียนเดิมยังอยู่ครบ ครูตั้งวันจริงได้ในตั้งค่า

## ลำดับติดตั้ง

1. ปิดหรือยกเลิกคาบที่ค้างอยู่ เลือกช่วงเวลาที่ไม่มีนักเรียนกำลังเช็คชื่อหรือเปลี่ยนรหัสผ่าน
2. ส่งออกรายงานที่ต้องการเก็บนอกระบบก่อนกดรีเซ็ต ไม่มีการสร้าง archive ในฐานข้อมูล
3. รันไฟล์ SQL ใหม่ให้สำเร็จ
4. Deploy โค้ดใหม่พร้อม `school-admin.js` และ `school-admin.css` แล้วโหลดหน้าเว็บใหม่/เข้าสู่ระบบใหม่
5. ตั้งค่าภาคเรียนและตรวจรายการห้องด้วยบัญชีครู ทดสอบ OTP และการส่งออกด้วยบัญชีทดสอบก่อนใช้งานจริง

SQL เปลี่ยนสิทธิ์ตารางคำขอรหัสผ่านให้ใช้ RPC เท่านั้น จึงต้อง Deploy หน้าเว็บใหม่ต่อเนื่องกับการรัน SQL หน้าเว็บรุ่นเก่าจะใช้การขอ/เปลี่ยนรหัสผ่านไม่ได้ในช่วงรอยต่อ และหลังรีเซ็ต คำขอบันทึกความคืบหน้าจากหน้าเก่าจะถูกปฏิเสธ

อย่ารันไฟล์ SQL ติดตั้งเดิมซ้ำหลัง migration นี้ เพราะอาจเปิดสิทธิ์ `password_reset_requests_public_all` กลับมา

## ภาคเรียนกับการรีเซ็ตต่างกันอย่างไร

- **บันทึกภาคเรียน**: เปลี่ยนชื่อและช่วงวันที่สำหรับหน้าจอ/รายงาน ไม่ลบข้อมูลนักเรียน
- **เริ่มเทอมใหม่และลบข้อมูลเดิม**: แสดงจำนวนข้อมูล เลือกภาคเรียน/ปี/วันที่ใหม่ ยืนยันผลกระทบ พิมพ์ข้อความยืนยัน และกรอกรหัสผ่านครู แล้วลบข้อมูลจริงใน transaction เดียว
- หากบันทึกชื่อภาคเรียนใหม่ไว้แล้ว สามารถเลือกภาคเรียนเดียวกับปัจจุบันในหน้าลบข้อมูลได้ แต่ยังต้องยืนยันครบทุกขั้นตอน
- รีเซ็ตไม่ได้ถ้ามีคาบเปิดหรือออเดอร์ pending ต้องปิดคาบและอนุมัติ/ปฏิเสธออเดอร์ก่อน
- เมื่อสำเร็จ ทุกเครื่องที่ใช้โค้ดใหม่จะรับสถานะผ่าน Realtime หรือ fallback polling 30 วินาที และให้เข้าสู่ระบบอีกครั้ง

## ข้อมูลที่ถูกลบ

ลบเฉพาะข้อมูลที่ผูกกับบัญชี role `STUDENT`: attendance_logs, redemption_logs, student_pets, student_pet_events, password_reset_requests และ student_free_item_notification_state ยอดคะแนน/XP/Level/เหรียญ/แต้มพิเศษเป็นค่าคำนวณจากข้อมูลเหล่านี้ จึงเริ่มต้นใหม่โดยไม่เก็บประวัติเทอมเดิมไว้

คงแถวนักเรียนทั้งหมด รวม ID, ชื่อ, ห้อง, password, photo_url และสถานะ first login ไว้ ไม่เรียก Storage delete ไม่ลบสินค้า รูปสินค้า โลโก้ สี ชื่อโรงเรียน หรือข้อมูลความคืบหน้าของบัญชีครู ตัวนับสัตว์เลี้ยงกลับไปเริ่มต้นเมื่อเลือกสัตว์เลี้ยงใหม่

ตัวนับ ID ของรายการไม่ถูกย้อนกลับ เพื่อไม่ให้เกิดรายการแจ้งเตือน/ออเดอร์คนละรายการแต่ใช้รหัสซ้ำ

## เมนูและห้องเรียน

เมนูหลักครูมี เช็คชื่อ, นักเรียน, ร้านค้า, รายงาน และปุ่มเฟืองสำหรับตั้งค่า ข้อมูลเข้าเรียนแบ่งรายคน/หลายคนหลายวัน/ประวัติ คำขอเปลี่ยนรหัสอยู่ในนักเรียน รายงานร้านค้าอยู่ในรายงาน ฟังก์ชันเดิมยังอยู่

ห้องมาจาก grade ของบัญชี STUDENT จริง ไม่สร้าง /1–/3 อัตโนมัติ “ทุกห้อง” ของชั้นเป็นตัวกรองรวมสำหรับสถิติ/รายงาน/แก้ข้อมูล/มอบของ ไม่ใช่ห้องสมมติสำหรับเปิดคาบ ฐานข้อมูลตรวจห้องซ้ำเมื่อเปิดคาบ ครูเพิ่มนักเรียนในห้องใหม่ได้จากตัวเลือกเพิ่มห้องใหม่ ระบบไม่ย้ายหรือเดาห้องให้ข้อมูลเดิม

## OTP

ขอรหัส → แจ้งครู/รับ OTP → ตรวจ OTP → ตั้งรหัสผ่านใหม่ แยกหน้าจอจริง ตรวจรหัสผ่านเซิร์ฟเวอร์ ไม่ส่ง OTP กลับให้นักเรียนผ่าน API คำขอ

OTP อายุ 15 นาที ผิดได้ไม่เกิน 5 ครั้ง เมื่อตรวจสำเร็จจะได้สิทธิ์เปลี่ยนรหัสครั้งเดียว อายุสูงสุด 5 นาทีและไม่เกินอายุ OTP รหัสผ่านเดิมไม่เปลี่ยนจนบันทึกขั้นตอนสุดท้ายสำเร็จ หากปิดหน้าตั้งรหัสก่อนสำเร็จ ให้ขอ OTP ใหม่

## โลโก้

อัปโหลดต้นฉบับคมชัดใหม่ ระบบย่อไม่เกิน 512px ด้วยตัวช่วยคุณภาพสูงเดิม เก็บ PNG เพื่อรักษาตัวหนังสือและพื้นหลังโปร่งใส ไม่ขยายภาพต้นฉบับเล็ก และไม่บีบอัดซ้ำเมื่อบันทึกตั้งค่า หน้าแรกแสดง 112px บนมือถือ/144px บนคอมพิวเตอร์ ไม่ครอปภาพ

ภาพเก่าที่เคยย่อเหลือ 80px ไม่สามารถเรียกรายละเอียดกลับได้ด้วยการขยาย CSS ต้องใช้ต้นฉบับใหม่ วิธีบีบอัดรูปโปรไฟล์นักเรียนไม่ได้เปลี่ยน

## ข้อจำกัดด้านสิทธิ์เดิม

คำสั่งใหม่ตรวจ token ครูและการรีเซ็ตตรวจรหัสผ่านครูซ้ำ OTP ย้ายออกจากการอ่านตารางโดยตรงแล้ว แต่ระบบล็อกอินและตารางอื่นยังใช้โครงสร้างเดิมที่มี password แบบข้อความและ policy `public_all` การอัปเดตนี้ไม่ใช่การย้ายระบบทั้งหมดไป Supabase Auth และไม่ควรตีความว่าช่องโหว่การเข้าถึงข้อมูลเดิมทั้งหมดถูกปิดแล้ว ต้องจัดการ Auth/RLS เป็นงานแยกก่อนอ้างว่าระบบปลอดภัยครบถ้วน

## การตรวจสอบ

- Impeccable อัปเดตเป็น 4.5.2 ใช้แนวทาง Operate, clarify, adapt, harden และตรวจ detector/ภาพจริง ไม่ให้คะแนน WCAG เต็มจากการดูภาพอย่างเดียว
- PostgreSQL จำลอง (PGlite): migration รันซ้ำ, ตรวจสิทธิ์, ห้องจริง, precondition/rollback, ลบข้อมูลจริง, คงบัญชี/รูป/รหัสผ่าน, ป้องกันคำขอเวอร์ชันเก่า, OTP ผิด/หมดอายุ/ใช้ซ้ำและสิทธิ์ตาราง
- Edge/Playwright: หน้าครูทุกเมนูและทุกรูปแบบแก้ไขที่ 320/390/768/1024/1280/1440px, ชื่อยาว, keyboard tabs, touch จำลองผ่าน CDP, ขยายข้อความ 200% บนหน้าครู, OTP สองหน้าจอ, การยกเลิกก่อนลบ, ห้องจริง และหน้าล็อกอิน/นักเรียน
- PDF หลายหน้า 6 ประเภทพร้อมชื่อภาคเรียน/หัวตารางซ้ำ และ CSV/Excel ผ่านการดาวน์โหลดจริง ตรวจ recovery เมื่อ query ล้มเหลว, timeout, cancel และโหลด stylesheet ไม่สำเร็จ
- Detector มีข้อเตือนจาก UI เดิมและ false positive เช่น Cropper ซ่อนต้นฉบับเพื่อวาดภาพใหม่, ฟอร์มพื้นโปร่งใสที่ถูกนับเป็นกล่อง และสี/เอฟเฟกต์รางวัลนักเรียนที่อยู่นอกหน้าครู ไม่อ้างว่า detector เป็นศูนย์หรือผ่าน WCAG AA ครบทุกข้อ
- ยังไม่ได้รัน migration กับ Supabase จริง ไม่ได้ทดสอบลบ production ไม่ได้ Deploy Vercel และยังไม่ได้ทดสอบอุปกรณ์ iOS/Android จริง

คำสั่งทดสอบ:

```powershell
npm install --prefix "$env:TEMP\mathquest-sql-qa" @electric-sql/pglite
node scripts/test-school-admin.cjs
node scripts/test-reports.cjs --browser
node scripts/test-school-ui.cjs
node scripts/serve.cjs 5173
```

Browser tests ต้องมี Playwright และ Edge ให้ตั้ง NODE_PATH เป็น path ของ dependency runtime เมื่อไม่ได้ติดตั้ง Playwright ในโปรเจกต์ Tests บล็อก Supabase production และใช้ fixture เท่านั้น
