# MathQuest: อนุมัติสิทธิ์ส่งคะแนนจาก ScanSob รายคำขอ

**สถานะ:** พัฒนาฝั่ง MathQuest ในเครื่องแล้ว ยังไม่ใช่หลักฐานว่าเปิดใช้จริงบน staging หรือ Production อ้างอิงสัญญาของ ScanSob checkout `a304e93`

## สิ่งที่เปลี่ยน

- โหมด `review_each_request` รับคำขอลงนามจากครูที่ ScanSob ยืนยันและอนุญาตให้จัดการ Workspace ของตน โดยไม่ต้องลงอีเมลใน MathQuest ก่อน ไม่มีคะแนนส่งเข้าได้จนกว่าแอดมิน MathQuest จะอนุมัติและ ScanSob บันทึก token ที่ผูกกับ Workspace/ปลายทางแล้ว
- โหมดเดิม `email_allowlist` เป็นค่าเริ่มต้นในการติดตั้ง migration การติดตั้งอย่างเดียวไม่เปลี่ยนการเปิดรับ รายชื่อ รอบ หรือ token เดิม
- เปลี่ยนโหมดหรือเปิดใหม่หลังพักจะออก `pairing_window_id` ใหม่ คำขอที่ค้างและบันทึกแล้วตรวจสถานะ/ยกเลิก/ตัดสินได้จนหมดอายุ การพักรับคำขอไม่เปิดทางรหัสเดิมกลับมา
- โหมดรายคำขอปิด `mq_scansob_admin('create_code')` และป้องกัน legacy `request` ที่ยังไม่เข้าคิว แม้จะถือรหัสที่ยังไม่หมดอายุ คำขอที่บันทึกแล้วใช้ challenge เดิมตรวจสถานะ/ยกเลิกได้ ไม่ลบการเชื่อมต่อหรือประวัติการส่งคะแนน
- Inbox แสดงผู้ส่ง อีเมล Workspace โรงเรียนปลายทาง เวลาส่ง และเวลาหมดอายุ เดิมมีเพียงผู้ดูแล Google ที่ตั้งไว้และมี teacher session จึงอ่าน ตั้งค่า หรือกดตัดสินใจได้ ผู้ส่งไม่ได้สิทธิ์เข้าหน้าแอดมินหรืออ่านทะเบียน

## SQL และสัญญา

ใช้ [20261117_02_scansob_review_each_request.sql](../20261117_02_scansob_review_each_request.sql) **ใน Supabase MathQuest** หลัง receiver 1.1 และ migration `20261116_01_scansob_code_free_pairing.sql` รุ่นที่มี window ID ไม่รัน migration เดิมซ้ำ SQL `20261117_01_scansob_publication_receipts.sql` เป็นงานรายงานแยก ส่วน SQL 024 เป็นของ ScanSob เท่านั้น

- `prepare_signed` รุ่น 1.0 คงฟิลด์ **ห้าฟิลด์**: `schema_version`, `action`, `request_id`, `destination_school_id`, `pairing_window_id` ไม่เพิ่ม policy หรือ capability ใน ACK เพราะฝั่ง ScanSob ใช้ strict schema
- `request_signed`, `status`, `revoke` และการส่งมอบ token คงรูปแบบเดิม การซ้ำคำขอที่รับแล้วตรวจจาก ID/Workspace/เนื้อหาเดิมก่อนตรวจนโยบายรับคำขอใหม่
- Error ใหม่ของ **legacy** `request` ที่เปิดรายการใหม่ไม่ได้: HTTP 409 `{"error":"LEGACY_PAIRING_DISABLED"}` ไม่ได้หมายถึงเพิกถอนสิทธิ์เก่า ไม่ควร fallback ไปกรอกรหัสใหม่
- ไม่แก้ `ingest-scansob-results` หรือสัญญาคะแนน 1.0 การส่งซ้ำ การถอนคะแนน และรายงานใบตอบรับไม่เปลี่ยน

## เปิดใช้บน staging

1. ตรวจ project และเวอร์ชันของ **Supabase MathQuest staging** ก่อนลง SQL ใหม่ แล้วปล่อยหน้าเว็บใหม่ ตรวจว่า Edge Function `pair-scansob-workspace` เป็นรุ่นที่รองรับทั้ง `prepare_signed` และ `request_signed` หากยังไม่ใช่ ให้ Deploy รุ่นจาก MathQuest 7e8113a หรือใหม่กว่าที่เข้าคู่กัน ไม่ต้อง redeploy ตัวรับคะแนนเพราะนโยบายนี้
2. ใช้ชื่อและรูปแบบค่าตั้งจาก [Handoff การลงนาม](20261116-scansob-code-free-pairing-handoff.md) ให้ตรงกันสองฝั่ง ฝั่ง ScanSob ตรวจ SQL 024 และค่า `MATHQUEST_CODE_FREE_PAIRING_ENABLED` / `MATHQUEST_CODE_FREE_PAIRING_RECEIVER_VERIFIED` ตามแผน staging เก็บคีย์แยกจาก Production ไม่ส่งค่า secret ในเอกสารหรือ Git
3. ใน MathQuest ไปที่ **ตั้งค่า → เชื่อมต่อ ScanSob → คำขอจาก ScanSob** กด **เปลี่ยนเป็นอนุมัติรายคำขอ** และยืนยัน ระบบพักรับคำขอใหม่ไว้ก่อนและเอาทางใช้รหัสออก เมื่อพร้อมทดสอบ ให้เปิด **เปิดรับคำขอใหม่** แล้วกด **บันทึกการรับคำขอ** ไม่ต้องกรอกอีเมล
4. ใช้ครู Google จำลองที่ ScanSob อนุมัติแล้วและไม่มีแถวในรายชื่อเก่า กดส่งคำขอ ตรวจกระดิ่ง/รายการใน MathQuest แล้วอนุมัติหนึ่งรายการ ปฏิเสธอีกหนึ่งรายการ ก่อนทดสอบส่ง/ถอนคะแนนจำลองด้วยการกดเอง ต้องตรวจฝั่ง ScanSob ว่าขณะอนุมัติยังเป็นโหมด manual และไม่มีงานส่งคะแนนสร้างขึ้นเอง
5. ทดสอบคำขอซ้ำ/เน็ตหลุด/กดสองแท็บ สลับรอบเปิดรับ ลองรหัสเก่าที่ไม่เคยใช้ ตรวจบัญชีนักเรียนและ Guest ว่าอ่าน inbox ไม่ได้ และยืนยันว่า token/ใบตอบรับเดิมยังทำงาน ตรวจผ่านครบจึงขออนุมัติ Production

**พักรับ:** ปิดสวิตช์เปิดรับแล้วบันทึก ไม่ต้องเปลี่ยนกลับเป็นนโยบายเดิม คำขอที่บันทึกไว้ยังจัดการได้ และ connection เดิมไม่ถูกเพิกถอน การย้อนกลับไปเปิดทางรหัสต้องเป็นการสลับนโยบายโดยเจตนาของผู้ดูแลผ่าน `mq_scansob_pairing_inbox('configure')` พร้อม teacher session และ revision ปัจจุบัน ไม่ทำอัตโนมัติเมื่อ ScanSob เชื่อมไม่ได้

## หลักฐานในเครื่องและสิ่งที่ต้องส่งจาก staging

- `scripts/test-scansob-signed-pairing.cjs`: ทดสอบ migration ซ้ำ ค่าเริ่มต้นคงโหมดเดิม ครูนอกรายชื่อสมัครได้หลังสลับ ลายเซ็น/ปลายทาง/รอบ คำตอบ Prepare แบบ strict การหยุดรหัสเก่า สิทธิ์ครู การตัดสินใจหลังพัก รับและถอนคะแนนของ connection เดิม และการเก็บรายชื่อไว้สำหรับ rollback
- `scripts/test-scansob-ui.cjs`: ทดสอบยืนยันเปลี่ยนโหมด หน้าไม่มีช่องอีเมลและรหัส เปิดรับโดยไม่ส่ง array อีเมล การอนุมัติ/ปฏิเสธ และ responsive ด้วย API จำลอง
- ให้บันทึก **HTTPS origin ของ Supabase staging + UUID โรงเรียนปลายทาง + commit ทั้งสองฝั่ง + migration + เวอร์ชัน Edge Function** และแนบผลทดสอบด้วยข้อมูลจำลอง ไม่ใช้ตัวเลขจากการรันในเครื่องแทนผล Deploy
